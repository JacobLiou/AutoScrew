## 0. 先记住：Demo「能打钉」≠ 参数路径已验证

仓库内 `src/SupplierDemo` 有三套示例，**能力不同**：

| Demo 目录 | 主要做什么 | 是否做 #100/#150 参数块 |
|-----------|------------|-------------------------|
| `…(GetResultStatus)` | DI / Ready / Finish 寄存器拧紧 | **否** |
| `…(ModbusTCP)` | DI + **#750/#751** 报告与曲线 | **否**（#751 Mode=11 是 550 word **快照**，不是参数表） |
| `…(ModbusTCP+FTP)` | 同上 + **FTP Bin** 曲线 | **否**（参数设置不靠这套） |

因此：

- 用 Demo **调通扳机 → Finish → 扭矩/曲线**，只证明 **TCP + DI/Finish（或 FTP）** 通。
- AutoScrew「拧紧参数」页走的是手册 **B.3.1 / A.3.1**：**#100 写 / #110 删 / #150 读**（外加列表 **#160**、激活 **#302**）。
- **不要**假设「Demo 参数页也有同源实现」；Demo 大多根本没实现 #100/#150。

功能码对照（驱动已映射，勿怀疑「码写错」）：

| 码 | 含义 | AutoScrew API / HMI |
|----|------|---------------------|
| **#100** | 参数写入（先写 0xD2×349，再邮箱） | 下发到设备 |
| **#110** | 参数删除 | `DeleteParameterAsync`（界面未必单独做按钮） |
| **#150** | 参数读取 | 从设备读取 / 导入选中 |
| **#160** | 已创建参数 ID 列表 | 刷新设备列表 |
| **#302** | 手动来源下切换参数 | 激活 |

## 1. 联调前强制条件（违反则全乱）

1. **同一 `IP:502` 只允许一个客户端**  
   关掉全部 Supplier Demo、其它上位机、PLC 二次连接。控制器多数不稳吃双客户端 → 典型症状：`Write registers 0xC8 len=10 failed`。
2. AutoScrew：`AutoScrew:UseSimulatedHardware=false`，设备连接页点 **应用**（测试连接 ≡ 应用，建立长连接）。
3. **作业拧紧进行中禁止改参数**（会话锁 `IsBusy`）；否则 Busy 或邮箱超时。
4. 记录现场：**Host / Port / ToolIndex(0|1) / 触发方式(Manual|AutoDi)** —— `#150/#100` 邮箱里带 ToolIndex。

## 2. 建议调试顺序（由浅到深）

按层证明「通 / 不通」，上一层失败不要改 Codec。

```text
① TCP 长连接
   ↓
② 邮箱最小命令（如 #562 / #406 / #533，与 Demo Init 类似）
   ↓
③ #160 列表 → 拿到真实 ParamID
   ↓
④ #150 读已知 ID（349 word）
   ↓
⑤ #100 原样回写 / 小改后写
   ↓
⑥ #300 切换方式=手动 → #302 激活
   ↓
⑦ 打钉（扳机或 AutoDi）→ #750/#751 或寄存器结果
```

### ① TCP

| 检查 | 期望 |
|------|------|
| 设备连接 → 应用 | 成功文案含 Host:Port |
| 随后立即「刷新设备列表」 | 不再报 `Modbus not connected` |
| 若过一会才炸 | 半开 TCP → 再点应用；确认无人抢 502 |

### ② 邮箱骨架（0xC8 → 0xCF）

任意成功命令都需：

1. （可选）先写数据区 **0xD2…**
2. 写 **0xC8** 起 **10 word**，其中 word0=功能码，某 word 置发送标志（实现里为 mailbox[6]=1）
3. 轮询 **0xCF~0xD1**：`[Cmd, 1, 0]` 成功；`[Cmd, 2, err]` 拒绝

驱动：`DeviceSession` 锁内完整走完；禁止 Demo+HMI 交叉写。

### ③–⑤ 参数链路（当前痛点重点）

**#150 成功包布局**（邮箱）：

`[150, 0, ToolIndex, ParamID, 0, 0, 1, 0, 0, 0]` → OK 后读 **0xD2～0x22E（349 word）**

**#100 成功顺序**：

1. 写满 **0xD2～0x22E（349 word）**
2. 邮箱 `[100, 0, ToolIndex, ParamID, …, 1, …]`
3. 等 0xCF OK

**#160**：只返回「有哪些 ID」，**不是**参数正文；列表空时不要死磕本地 JSON 的「参数 1」。

### ⑥ 激活

`#302` 要求拧紧来源切换方式为 **手动（#300 CC=0）**。Apply 时驱动会 `EnsureManualSource`；若在来源页改成扫码/选择器再测 #302，会 code 1。

### ⑦ 打钉

- **Manual**：软件进周期后等电批扳机；状态「请按扳机」。
- **AutoDi**：软件写 DI bit0，对齐 GetResultStatus Demo。
- 曲线：α 默认 **#750/#751**；FTP Demo **不是** AutoScrew 默认路径。

## 3. 现象 → 原因速查

| 现象 | 更可能原因 | 先做什么 |
|------|------------|----------|
| `Write registers 0xC8 len=10 failed` | 双客户端 / TCP 半死 / 大包写坏会话 | **关 Demo** → 再应用 → 先只做 #150 |
| `Modbus not connected` | 长连接断了仍持有 client | 再应用；确认 Ensure 靠 `IsConnected` |
| `Command #150 rejected` + **DeviceErrorCode=3** | **该 Tool 下无此 ParamID** | 刷新 #160；换真实 ID；勿信「本地预设 001」 |
| `#150` code **2** | ToolIndex 越界/轴不对 | 设备连接改 Tool 0/1 后应用 |
| `#160` 空列表 | Tool 不对 / 位图解析与固件不一致 / 控制器无「已创建集」 | 换 Tool；控制器 HMI 确认参数所在轴；直接填已知 ID 试 #150 |
| `#100` rejected + code 18 等 | 扭矩超工具规格等校验 | 看 `TighteningParameterErrorCodes` 中文表；降扭矩 |
| `#302` code 1 | 非手动切换 | 来源页改为手动；重新 Apply |
| Demo 曲线很全、作业台空 | Demo 走 FTP；作业台走 #751；NG 遮罩挡图 | 看日志 `#751 failed`；先解锁 NG；对照 ModbusTCP（无 FTP）Demo |
| 作业中改参数全炸 | 抢会话锁 | 等周期结束；Busy 时按钮应灰 |

异常只看英文 `Command #150 rejected…` 不够：打开异常属性 **`DeviceErrorCode`**，或 HMI 已映射的中文（`TighteningParameterErrorCodes` / `ModbusCommandErrorCatalog`）。

## 4. 与 SupplierDemo 对照时怎么用

1. **验证「链路」**：开 **ModbusTCP** Demo（关 FTP 版若只需寄存器），只连一台枪，完成一轮拧紧 → 说明本机网段/IP/Slave 正确。
2. **立刻关掉 Demo**，再开 AutoScrew 应用。
3. **不要**在 Demo 里找「写参数」按钮对照 AutoScrew；参数请用：
   - 控制器本机 HMI（建参数、确认 Tool/ID），或
   - AutoScrew「拧紧参数」#160→#150→#100，或
   - 临时写一小段只发 #150 的 console（若需要）对照邮箱 10 word。
4. **扭矩单位**：控制器内部多为 mNm 存整数；HMI 显示 Nm。Demo 结果串里的 `Param ID` 只是本次拧紧用过的 ID，**不等于**该 ID 此刻一定能 #150 读通。

## 8. 网口调试工具：原生指令全集（先裸试再调上位机）

本章用途等同「串口调试助手」：用 **Modbus TCP 调试工具**（如 Modbus Poll、ModScan、QModMaster、厂商工具等）直连控制器，**不经过 AutoScrew**，先确认原生帧是否通。

### 8.1 连接与工具设置

| 项 | 值 |
|----|-----|
| 协议 | **Modbus TCP** |
| IP | 现场控制器（默认手册常为 `192.168.1.11`；你们现网常见 `169.254.40.13`） |
| 端口 | **502** |
| Unit/Slave ID | 通常 **1**（与 `ModbusSlaveId` 一致） |
| 地址基址 | Demo/本驱动：保持寄存器地址用 **十六进制数值直接填**（如 `0xC8` = 十进制 **200**），**不是** `40001+偏移` |
| 独占 | 调试时 **关掉 AutoScrew / Demo / 其它主站** |

工具里一般勾：

- **03H** Read Holding Registers  
- **06H** Write Single Register  
- **10H** Write Multiple Registers  

单次多寄存器长度：手册示例偏保守；本仓 Demo/驱动大块常按窗口分段（如 ≤120 word/帧）。网口工具若一次写 349 word 失败，改为分段写 `0xD2` 再发邮箱。

### 8.2 两类「指令」：直写寄存器 vs 命令邮箱

```text
【直写寄存器】FC06/10 → 地址/数值          （DI、Ready、Finish…）
【命令邮箱】   先写 0xD2? → 再写 0xC8×10 → 轮询 0xCF×3 → 再读 0xD2?
```

#### 邮箱 10 word 布局（写到起始地址 **0xC8 / 200**）

| Word 下标 | 常见含义 | 固定习惯 |
|-----------|----------|----------|
| 0 | 功能码 Cmd（如 150、100、302） | — |
| 1 | 版本 / 保留 | 多为 `0` |
| 2 | 视命令：Tool / ReportL / … | — |
| 3 | 视命令：ParamID / ReportH / … | — |
| 4 | 视命令：ScrewCountL / Mode / … | — |
| 5 | 视命令：ScrewCountH / … | — |
| **6** | **发送标志** | **必须写 `1` 才真正触发命令** |
| 7–9 | 保留 | `0` |

驱动实现：`CommandMailbox.CreateRequest` → `[Cmd, w1, w2, w3, w4, w5, 0,0,0,0]`，发送前再把 **[6]=1**。

#### 应答（读起始地址 **0xCF / 207**，长度 3）

| Word | 成功 | 失败 |
|------|------|------|
| 0 | = Cmd | = Cmd |
| 1 | **1** | **2**（拒绝） |
| 2 | **0** | **设备错误码**（如 #150→3=未配置该 ID） |

超时：轮询约 50ms×若干，Demo 常见总超时 ~3s。

#### 数据区

| 地址 | 十进制 | 用途 |
|------|--------|------|
| **0xD2** | 210 | 读回 / 写下发电邮前数据块起始 |
| **0x22E** | 558 | 参数块结束（#100/#150 → **349 word**） |

**操作类型（与代码目录一致）**

| 类型 | 步骤 |
|------|------|
| MailboxOnly | 只写 `0xC8`×10 → 等 `0xCF` |
| WriteThenMailbox | 先 `10H` 写 `0xD2…` → 再邮箱 |
| MailboxThenRead | 邮箱 OK → 再 `03H` 读 `0xD2` 起 N word |

### 8.3 常用直写/直读寄存器（打钉相关，无邮箱）

| 地址 Hex | 十进制 | R/W | 说明 | 网口示例 |
|----------|--------|-----|------|----------|
| **0x67** | 103 | R | DI 状态；Bit0=1 表示 DI 已应答 | FC03 地址 103 len=1 |
| **0x68** | 104 | W | DI 命令；写 **1** 触发 AutoDi 拧紧，写 **0** 清除 | FC06 地址 104 = 1 或 0 |
| **0x6B** | 107 | R | 履历 ID 低 word | 与 0x6C 组成 DWORD |
| **0x6C** | 108 | R | 履历 ID 高 word | `ID = High*65536 + Low` |
| **0x24** | 36 | R | Total Angle | GetResultStatus 轻量 |
| **0x26** | 38 | R/W | 拧紧结果（旧）；1=OK 2=NG；可写 0 清 | Legacy Finish |
| **0x1F46** | 8006 | R | Final+Prevail 扭矩低 | DWORD /1000 → N·m |
| **0x1F47** | 8007 | R | 扭矩高 | |
| **0x1F52** | 8018 | R | Ready；**==1** 才宜发 DI | |
| **0x1F5D** | 8029 | R/W | Finish（新）；1=OK 2=NG 5=Pass；读后写 **0** 清除 | α 默认用此 |

**裸打钉最小序列（对齐 GetResultStatus Demo）**

1. 读 `0x1F52` == 1  
2. 写 `0x68` = 0 → 读 `0x67` bit0 == 0  
3. 写 `0x68` = 1 → 等 `0x67` bit0 == 1  
4. 轮询 `0x1F5D` 直至 1/2/5  
5. 读角度 `0x24`、扭矩 `0x1F46–0x1F47`  
6. 写 `0x68` = 0；写 `0x1F5D` = 0

### 8.4 联调优先：可复制的邮箱 10 word（十进制）

以下均：**FC10，起始地址 200（0xC8），长度 10**。`tool`/`paramId`/`seqId`/`reportL`/`reportH` 换成现场值。

| 目的 | 10 个 word（空格分隔） | 成功后 |
|------|------------------------|--------|
| #562 曲线采样率 | `562 0 0 0 0 0 1 0 0 0` | 部分固件回读在 0xC8；或看驱动 `Readback` |
| #533 AutoLock 开 | `533 0 1 0 0 0 1 0 0 0` | 仅邮箱 |
| #533 关 | `533 0 0 0 0 0 1 0 0 0` | 仅邮箱 |
| #406 限制拧紧/解锁类 | `406 0 0 0 0 0 1 0 0 0` | 仅邮箱 |
| #160 参数列表 | `160 0 tool 0 0 0 1 0 0 0` | 读 `0xD2` 起建议 100～500 word |
| #150 读参数 | `150 0 tool paramId 0 0 1 0 0 0` | 读 `0xD2` **349** word |
| #110 删参数 | `110 0 tool paramId 0 0 1 0 0 0` | 仅邮箱（慎用） |
| #100 写参数 | 先写满 `0xD2`×349，再 `100 0 tool paramId 0 0 1 0 0 0` | 等 CF |
| #300 来源手动 | `300 0 tool 0 0 0 1 0 0 0` | `[Cmd,0,Tool,Operating,Switching,…]`；Operating=0 单工具，**Switching=0 手动** |
| #302 切换参数 | `302 0 tool paramId screwL screwH 1 0 0 0` | 须已手动来源 |
| #303 切换顺序 | `303 0 tool seqId 0 0 1 0 0 0` | 须已手动来源 |
| #250 读顺序 | `250 0 tool seqId 0 0 1 0 0 0` | 再读 `0xD2`（顺序块约 530 word，见手册） |
| #200 写顺序 | 先写 `0xD2` 顺序块，再 `200 0 tool seqId … 1 …` | |
| #260 顺序列表 | `260 0 0 0 0 0 1 0 0 0` | 读 `0xD2` |
| #350 读来源模式 | `350 0 0 0 0 0 1 0 0 0` | 读 `0xD2` 小块 |
| #750 读报告 | `750 0 reportL reportH 0 0 1 0 0 0` | 读 `0xD2` **253** word |
| #751 曲线 Scale | `751 0 reportL reportH 10 0 1 0 0 0` | Mode=10；读 `0xD2`（Scale 等，见 driverAnaC） |
| #751 角度块 | `751 0 reportL reportH mode 0 1 0 0 0` | Mode 依点数分段（Demo） |
| #517 BIN 开 | `517 0 3 0 0 0 1 0 0 0` | FTP 路径用；α 默认不依赖 |
| #517 BIN 关 | `517 0 0 0 0 0 1 0 0 0` | |
| #401 写条码 | 视手册；常先数据区或把字塞邮箱——以手册 A 为准 | AutoScrew: `WriteBarcodeAsync` |
| #402 清错 | `402 0 0 0 0 0 1 0 0 0` | |
| #552 固件版本 | `552 0 0 0 0 0 1 0 0 0` | 读 `0xD2` |
| #650 工具信息 | `650 0 tool 0 0 0 1 0 0 0` | 读 `0xD2` |

**网口试参推荐最短路径**

1. `#562`（证明邮箱活着）  
2. `#160` + 读 `0xD2`（拿到真实 ID）  
3. `#150` + 读 349 word（证明参数块）  
4. （可选）把刚读的 349 word **原样**写回 `0xD2`，再 `#100`（证明写路径）  
5. `#300` 手动 → `#302`  
6. 直写 DI / 扳机完成一轮 → `#750`

若第 1 步就 `0xC8` 写失败：查网线/IP/双主站，**不要先怀疑参数布局**。
