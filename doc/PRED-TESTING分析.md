
# PRED-TESTING 账号 UDL等



**文件夹 ACL（只有 PRED-TESTING 能进）** 和 **进程占用（COM Server / 驱动层 UDL 把 DLL 锁住）** 是两层限制：

| 层 | 作用 | PRED-TESTING 能否单独解决 |
|----|------|---------------------------|
| ACL | 谁能进目录、谁能写 | 能（高级文件页就是干这个） |
| 文件锁 / 服务常驻 | 谁正在用这个文件 | **不能**，必须先停进程/服务 |

所以正确流程一般是：

1. **停** COM Server / UDL 相关服务与进程（必要时管理员策略下才有停服权限）  
2. **替换** 目录（此时用 PRED-TESTING 才有写权）  
3. **再启动** 服务/进程  
4. 若厂商要求或接口变了，再处理 **COM 注册**（`regsvr32` / 安装程序 / 厂商文档里的注册步骤）——不是每次覆盖都要，但换了 COM DLL/TLB 时经常要

「管理员限制死」在这里通常表现为：服务由系统策略托管、普通操作员停不了服务；即便你用 PRED-TESTING 有目录写权，**不停服也换不了正在加载的 dll**。

高级文件页目前只覆盖第 2 步（鉴权后的拷贝），不会自动做 1/3/4。若以后要做成向导式「停服 → 同步 → 启服（+可选注册）」，需要单独做成功能并确认现场服务名与权限。
